# Как участвовать в «РЕЛИКТЕ»

Дополнения принимаются через pull request в ветку `main`. Можно предложить инцидент, существо, аномалию, развитие сюжета, редактуру или техническое улучшение. Канон утверждает автор проекта, [@meshushkevich](https://github.com/meshushkevich).

## Перед началом

Прочитайте [правила проекта](AGENTS.md), нужные главы [основного сюжета](src/index.md), [свойства ГБС](src/Spoilers/gbs.md) и [решения с открытыми вопросами](src/Spoilers/decisions.md). Найдите связанные материалы в приложениях. Для крупного сюжетного направления сначала откройте issue: это поможет обсудить замысел до написания полного текста.

Агент может помочь с идеей, текстом и проверкой, но не принимает решение за автора. За содержание PR отвечает его создатель.

## Что и куда добавлять

- Главы основного сюжета: сейчас пишется первая глава «Предыстория», от открытия ГБС до блокады 2005 года; будущие главы пока не определены. Папка: `src/Chapters/`; обязательны YAML-поля `title` и `status`. Новая глава до утверждения остаётся `draft` вне оглавления.
- Инциденты: `src/Incidents/`.
- Существа: `src/Creatures/`.
- Аномалии: `src/Anomalies/`.
- Авторские пояснения и рабочие альтернативы: `src/Spoilers/`.

Используйте [шаблоны](templates/README.md). Новый материал получает `status: draft`; он остаётся в тематической папке, но не попадает в `src/SUMMARY.md`, читательские указатели и основной сюжет до утверждения. Добавьте его в редакционный `README.md` раздела. Проверьте, что номер инцидента свободен: номер 006 уже занят черновиком.

Для изменения действующего канона подготовьте отдельное черновое предложение в авторских заметках со ссылкой на исходник и перечислите предлагаемые изменения в PR. Не подменяйте действующую версию до решения автора. Опечатки и редактура без изменения фактов могут исправляться прямо в исходном файле с сохранением `canon`.

В делах и карточках сохраняйте ограниченные знания составителей. Первые три инцидента не раскрывают ГБС, хотя основной сюжет сообщает читателю скрытые причины. Не назначайте неизвестные даты, не вводите новые законы биологии ради объяснения одной сцены.

## Как открыть PR

1. Сделайте fork репозитория и создайте рабочую ветку, например `addition/incident-007`.
2. Подготовьте одно связное дополнение. Не смешивайте переписывание сюжета с несвязанными техническими правками.
3. Выполните проверки ниже и создайте коммит в своей ветке.
4. Откройте PR из fork в `meshushkevich/Project-Relict:main`, заполните шаблон и перечислите новые факты. Для незаконченной работы используйте Draft PR.
5. После доработки снимите статус Draft PR. GitHub запросит проверку @meshushkevich через [CODEOWNERS](.github/CODEOWNERS).

Слова Draft PR описывают состояние заявки на GitHub. Поле `status: draft` описывает состояние текста во вселенной; это разные статусы.

## Проверки

Нужны [uv](https://docs.astral.sh/uv/getting-started/installation/), Rust/Cargo и mdBook 0.5.4. Команды выполняются из корня проекта. Требование к версии Python указано в `pyproject.toml`; uv может установить подходящий интерпретатор автоматически. В CI используется Python 3.12. Зависимости проверок описаны в `pyproject.toml`, точные версии зафиксированы в `uv.lock`.

```sh
uv sync --locked
cargo install mdbook --version 0.5.4 --locked
uv run --locked python -m unittest discover -s tests
uv run --locked python scripts/check_content.py
uv run --locked mdbook build
uv run --locked python scripts/check_content.py --book-dir book
```

Активировать `.venv` вручную не нужно: `uv run` запускает команды в окружении проекта. Если меняете Python-зависимости, обновите `pyproject.toml`, выполните `uv lock` и включите оба файла в PR. Обычные проверки с `--locked` не обновляют lock-файл.

Проверяются YAML, обязательные поля, даты, уникальность номеров, отсутствие черновиков в оглавлении и локальные ссылки. После сборки проверяются ссылки и якоря HTML-книги. CI также запускает тесты валидатора и сборку mdBook. Скрипты не оценивают литературное качество и не подтверждают соответствие канону: это проверяет автор.

Для PR из fork первая проверка GitHub Actions может ожидать разрешения владельца репозитория. Разрешение запустить CI не означает утверждения текста.

## Как текст становится каноном

Автор может принять PR с новым материалом **как черновик**. Он будет храниться в `main`, сохраняя `status: draft` и не появляясь в книге. Само слияние такого PR не утверждает сюжет.

Для включения в канон нужен явный ответ @meshushkevich: какие факты или какой текст утверждены. Затем в том же PR либо отдельной заявке обновляются статус, затронутые документы, основной сюжет, оглавление и [журнал решений](src/Spoilers/decisions.md). Журнал ссылается на PR с решением автора; он не служит доказательством одобрения сам по себе.

Перед слиянием окончательного варианта нужны успешная проверка `Book validation`, разрешённые обсуждения и Approve от @meshushkevich. После изменения содержимого прежнее одобрение сбрасывается. Положительный отзыв другого участника или агента не заменяет авторское одобрение.

## Настройки GitHub

Все файлы закреплены за @meshushkevich через CODEOWNERS. Для `main` требуется PR с одобрением владельца файлов и успешной проверкой `Book validation`; force push и удаление ветки запрещены. Конфигурация сохранена в [branch-protection.json](.github/branch-protection.json); статус защиты можно проверить в [настройках веток](https://github.com/meshushkevich/Project-Relict/settings/branches). Проверка `Book validation` принимается только от GitHub Actions.

Для администратора сохранён обход защиты: автор не может одобрить PR, который создал сам. Обход предназначен для собственных изменений автора. Добавление других администраторов меняет границы этого исключения; список обязательных владельцев файлов остаётся решением автора.

Справка GitHub: [CODEOWNERS](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/about-code-owners), [защищённые ветки](https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/managing-protected-branches/about-protected-branches).
