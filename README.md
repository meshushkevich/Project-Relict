# РЕЛИКТ

Оригинальная русскоязычная хоррор-вселенная: закрытый научный город Озёрск-9 на Кольском полуострове, Россия, 2005 год. Озёрск-9 вымышлен; история использует альтернативную географию и расходится с реальной историей.

Материалы развиваются постепенно в Markdown. Документы внутри мира передают наблюдения и версии своих составителей, а не всеведущее объяснение происходящего.

## Разделы

[Основной сюжет](src/index.md) читается одной связной хроникой: от открытия ГБС в начале 1980-х до блокады Озёрска-9 в 2005 году. Остальные материалы собраны в приложения; ссылки на них расположены в соответствующих частях хроники.

- [Предыстория](src/background.md) — приложение с предысторией и событиями 2005 года.
- [Существа](src/Creatures/README.md) — отдельные живые формы.
- [Аномалии](src/Anomalies/README.md) — необычные объекты, места и процессы.
- [Инциденты](src/Incidents/README.md) — реестр событий и материалы дел.
- [Авторская база — спойлеры](src/Spoilers/README.md) — свойства ГБС, реестр датированных дел и авторские решения. Раздел завершает приложения. Основной сюжет тоже раскрывает скрытые причины событий.

## Работа над историей

Дополнения принимаются через PR из fork в `main`. Прочитайте [инструкцию для участников](CONTRIBUTING.md): там описаны работа с черновиками, проверки и порядок рассмотрения. Канон утверждает [@meshushkevich](https://github.com/meshushkevich); остальные участники предлагают материалы и правки.

[AGENTS.md](AGENTS.md) содержит правила совместной работы, порядок утверждения канона и указатель скиллов в [.agents/skills](.agents/skills/). [Шаблоны](templates/README.md) помогают создавать новые документы.

Новые материалы получают статус `draft`; только автор переводит их в канон. PR можно принять как черновик без утверждения сюжетных фактов. Для слияния чужих изменений требуются успешная проверка `Book validation` и одобрение автора через CODEOWNERS. Черновики лежат в соответствующих тематических разделах. `canon` означает утверждённый документ, но не достоверность каждой изложенной в нём гипотезы.

## Книга mdBook

Для сборки нужны [Rust и Cargo](https://www.rust-lang.org/tools/install), Python 3 и [mdBook](https://rust-lang.github.io/mdBook/). Python используется для обработки редакционных метаданных, проверки статуса глав и ссылок авторского раздела. Для окружения проверок используется [uv](https://docs.astral.sh/uv/); зависимости описаны в `pyproject.toml` и зафиксированы в `uv.lock`.

Установить проверенную версию mdBook:

```sh
cargo install mdbook --version 0.5.4 --locked
```

Из корня проекта:

```sh
uv sync --locked
uv run --locked mdbook build
uv run --locked mdbook serve --hostname 127.0.0.1 --port 3000
```

`build` сохраняет HTML-книгу в `book/`, `serve` запускает локальный просмотр по адресу http://127.0.0.1:3000 и пересобирает книгу при изменении исходников. Папка `book/` исключена из Git. Автоматическая публикация не настроена.

### Организация исходников

```text
src/
├── SUMMARY.md             # порядок чтения
├── index.md               # основной сюжет, связная хроника
├── background.md          # приложение с предысторией
├── Incidents/             # тексты дел и навигация
├── Creatures/             # карточки существ и навигация
├── Anomalies/             # карточки аномалий и навигация
└── Spoilers/              # авторские главы в конце книги
templates/                 # шаблоны для новых документов
scripts/                   # обработка метаданных при сборке
book.toml                  # конфигурация mdBook
book/                      # результат сборки, исключён из Git
```

Все тексты книги находятся непосредственно в `src/`. Здесь нет файлов-включений: каждое дело или карточка редактируется в одном месте. [Оглавление](src/SUMMARY.md) задаёт состав и порядок чтения.

В каждом тематическом разделе `index.md` служит читательским указателем, а `README.md` содержит редакционный реестр или инструкции для соавторов. Редакционные страницы не включены в оглавление книги. В реестре инцидентов видны и утверждённые дела, и черновики.

### Добавление и публикация текста

1. Скопируй подходящий [шаблон](templates/README.md) в `src/Incidents/`, `src/Creatures/` или `src/Anomalies/`. Новый текст получает `status: draft`.
2. Добавь документ в редакционный `README.md` раздела. Авторские пояснения храни в `src/Spoilers/`, со ссылкой на исходник.
3. После утверждения автором добавь событие в основной сюжет, если оно развивает историю. Подробный документ включи в приложения через `src/SUMMARY.md` и указатель раздела; поставь ссылку на него в соответствующей части хроники.
4. Выполни `mdbook build` и проверь страницы и ссылки. Между исходниками используй обычные относительные ссылки на `.md`.

Основной сюжет расположен на главной странице. После него под заголовком «Приложения» идут предыстория, дела 001–005, указатели существ и аномалий, последними — авторские материалы из `src/Spoilers/`. Черновое дело 006 хранится в `src/Incidents/`, но не включено в оглавление. Как и редакционные `README.md` основных разделов, оно не попадает в страницы, поиск и печатную версию. Шаблоны и инструкции агента остаются за пределами `src/`. Авторские материалы доступны в книге, её поиске и печатной версии; раздел помечен как содержащий спойлеры. Их публикация не утверждает рабочие гипотезы и черновики.

Не размещай в `src/` статические файлы с авторскими раскрытиями: не относящиеся к главам ресурсы могут копироваться при сборке. Для материалов, которые пока не предназначены к публикации, используй Markdown-документы вне оглавления. Авторская база теперь включена в книгу.

Препроцессор [scripts/mdbook_metadata.py](scripts/mdbook_metadata.py) проверяет `status: canon` у включённых документов и убирает YAML из отображаемого текста. Если в оглавление добавлен черновик или документ без метаданных, сборка завершается ошибкой. Поле `status` записывается одной строкой; значение `canon` можно указывать без кавычек, в одинарных или двойных кавычках.

Проверяй, что цели ссылок читательских документов тоже включены в оглавление. Авторские пояснения включаются только в последний раздел «Авторские материалы — спойлеры». Новые главы этого раздела добавляй после основных материалов; его `README.md` служит вступлением. Ссылки из авторских глав на Markdown-документы вне оглавления в книге отображаются как текстовые подписи, сохраняя исходные ссылки в Markdown.


### Проверки для PR

Зависимости и команды полного цикла приведены в [CONTRIBUTING.md](CONTRIBUTING.md). После `uv sync --locked` выполните:

```sh
uv run --locked python -m unittest discover -s tests
uv run --locked python scripts/check_content.py
uv run --locked mdbook build
uv run --locked python scripts/check_content.py --book-dir book
```

GitHub Actions повторяет эти проверки для PR и ветки `main`. Они проверяют формат, метаданные и ссылки; решение о каноне принимает автор.
